# 业务影响分析与根因定位监控系统 — 需求文档

## 1. 背景与目标

现有工具仅统计监控项覆盖率，无法支撑线上故障的快速响应。本系统面向运维一线人员，
在故障发生时回答三个问题：**出了什么问题、影响哪些业务、根因在哪里**，并给出
应急处置建议。

### 1.1 核心目标（1-15-30）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 发现（MTTD） | ≤ 1 分钟 | 从异常发生到产生告警并推送到一线 |
| 定位（MTTL） | ≤ 15 分钟 | 从告警到锁定根因组件/变更 |
| 解决（MTTR） | ≤ 30 分钟 | 从告警到业务恢复（含应急处置） |

### 1.2 设计原则

- **业务视角优先**：一线人员先看到"业务受损程度"，再下钻到技术细节。
- **少即是多**：默认界面只呈现当前需要处置的故障，不堆砌全部指标。
- **结论先行**：系统给出可执行结论（疑似根因 + 处置建议），而非只给原始数据。
- **可解释**：每个根因判断都附带支撑证据，供人工确认，不做黑盒决策。
- **不重复造轮子**：复用现有监控工具与 ES，本系统定位为"关联分析与决策层"，
  不替代底层采集与存储。

### 1.3 技术现状与系统约束

本系统建设在既有监控体系之上，需对接以下现状：

| 维度 | 现状 |
| --- | --- |
| 应用监控 | 自研应用监控工具采集（指标 + 调用链 + 应用日志） |
| 系统监控 | 采购的系统监控工具采集基础设施指标与事件 |
| 数据存储 | 指标与日志统一存储在 Elasticsearch（ES）集群 |
| 应用规模 | 约 400+ 套应用，主体为腾讯 TSF 框架微服务 |
| 基础设施 | 操作系统、TDSQL、GaussDB、TBDS、CRedis、网络、硬件、外设、动环 |

关键约束与设计取向：

- **ES 作为统一数据底座**：本系统优先通过 ES 查询/聚合获取指标与日志，
  不新建一套采集链路；对两套监控工具的告警/事件做标准化接入。
- **数据模型标准化**：自研工具与采购工具的对象命名、标签需归一化映射，
  以便跨工具关联（如同一台主机在两套工具中能对应）。
- **面向 TSF 微服务**：拓扑发现、调用链、实例维度均需适配 TSF 的
  服务/实例/部署组模型，并对接其注册中心与服务治理数据。
- **分层下钻**：定位路径需覆盖"业务 → TSF 微服务 → 服务实例 →
  基础设施（OS/数据库/缓存/网络/硬件/动环）"全链路。

## 2. 用户角色

| 角色 | 关注点 | 主要场景 |
| --- | --- | --- |
| 运维一线（值班） | 现在有没有事、严不严重、我该做什么 | 故障大盘、应急处置 |
| 运维专家/SRE | 根因细节、历史趋势、误报治理 | 根因下钻、规则调优 |
| 业务/管理者 | 业务影响范围与时长 | 影响概览、复盘报告 |
| 系统管理员 | 接入配置、权限、数据源 | 配置管理 |

## 3. 功能需求

### 3.1 故障发现与告警（支撑"1 分钟发现"）

- **FR-1.1 多源数据接入**：
  - 指标与日志统一从 **ES** 查询接入，按需建立索引模板与查询适配层；
  - 接入**自研应用监控工具**的指标、调用链、应用日志；
  - 接入**采购系统监控工具**的基础设施指标与告警事件；
  - 接入事件类数据：发布/配置变更、扩缩容、工单、动环告警；
  - 对两套工具的对象与标签做归一化映射（主机、IP、服务名对齐），
    保证跨工具可关联。
- **FR-1.2 异常检测**：支持静态阈值、同比/环比、动态基线三种检测方式；
  关键业务指标检测周期 ≤ 30 秒；对 ES 中的 error/异常日志支持基于
  关键字、日志模板（pattern）与突增速率的检测。
- **FR-1.3 告警收敛**：对同一故障的多条告警按业务/拓扑维度聚合为单一"故障事件"，
  避免告警风暴；要求聚合后噪声率下降 ≥ 80%。
- **FR-1.4 分级与推送**：按业务影响自动定级（P1-P4），通过站内、短信、IM、电话
  分级触达；P1 推送延迟 ≤ 1 分钟。
- **FR-1.5 告警闭环**：每条故障事件具备状态机（新建 → 已认领 → 处置中 → 已恢复 →
  已复盘），全程留痕。

### 3.2 业务影响分析（回答"影响什么业务"）

- **FR-2.1 业务-应用-资源拓扑（五层模型）**：维护并自动发现以下分层依赖拓扑——
  1. **业务服务层**：对外业务/交易；
  2. **微服务层**：TSF 微服务（从注册中心/调用链自动发现服务及其依赖）；
  3. **实例层**：TSF 服务实例 / 部署组 / 容器；
  4. **基础设施层**：操作系统、TDSQL、GaussDB、TBDS、CRedis、网络设备、
     硬件、外设；
  5. **环境层**：动环（机房动力与环境）。
  支持基于 TSF 调用链自动发现微服务依赖，基础设施关系支持 CMDB 导入与手工维护。
- **FR-2.2 影响面计算**：故障发生时，自动沿拓扑上钻，列出受影响的业务服务、
  预估受影响用户数/交易量、关联的核心链路。
- **FR-2.3 业务健康度**：每个业务服务用统一健康分（成功率、时延、流量综合）表达，
  红/黄/绿三态，一线无需理解底层指标即可判断严重性。
- **FR-2.4 影响时间线**：以时间轴呈现"指标恶化 → 告警 → 业务跌量 → 恢复"过程，
  量化业务损失（受损时长、损失交易量）。

### 3.3 根因定位（支撑"15 分钟定位"）

- **FR-3.1 逐层下钻定位**：沿五层拓扑一键逐层下钻——业务服务 → TSF 微服务 →
  服务实例 → 基础设施（OS/TDSQL/GaussDB/TBDS/CRedis/网络/硬件/外设）→ 动环；
  每一层只展示该层异常对象并标注异常证据（指标、日志、事件），
  下钻路径默认自动收敛到异常子树，一线人员沿红色路径点到底即可。
- **FR-3.2 数据库/中间件专项视图**：针对 TDSQL、GaussDB、TBDS、CRedis 提供
  专项排查视图（如慢 SQL/锁等待、连接数、主从延迟、缓存命中率/大 key、
  消息积压），下钻到具体实例时直接呈现该类组件的关键指标。
- **FR-3.3 错误日志快速排查（核心）**：下钻到任意异常对象时，一键拉取该对象
  在故障时间窗内的 error/异常日志，详见 3.4 节。
- **FR-3.4 变更关联**：自动关联故障时间窗内的 TSF 发布、配置变更、扩缩容、
  工单与动环事件，按时间相关性排序（变更是最常见根因，需优先呈现）。
- **FR-3.5 根因候选排序**：综合异常传播方向、指标相关性、错误日志聚类、
  变更关联、历史相似故障，输出 Top-N 疑似根因，每项给出置信度与支撑证据，
  并标注根因所在层级（应用 / 数据库 / 网络 / 硬件 / 动环）。
- **FR-3.6 关联分析**：支持指标 / 日志 / 调用链三态联动——选定时间点可同时
  查看对应的错误日志样本与慢调用链。
- **FR-3.7 相似故障检索**：基于故障特征检索历史相似事件，复用其根因与处置过程。

### 3.4 错误日志快速排查（基于 ES）

针对"快速排查日志里的 error 和报错"的核心诉求，专设此模块：

- **FR-LOG-1 上下文直达**：从任意故障/异常对象（业务、微服务、实例、数据库）
  一键跳转到其错误日志视图，自动带入对象标识与故障时间窗，无需手工写 ES 查询。
- **FR-LOG-2 错误日志聚合**：对 ES 中的 error/exception 日志做模板聚类
  （按异常堆栈/日志模板归并），呈现"错误类型 + 出现次数 + 首次/末次时间 +
  影响实例数"，避免一线在海量日志中逐条翻找。
- **FR-LOG-3 突变识别**：自动标出故障窗内**新出现**或**突增**的错误类型，
  并与历史基线对比，优先把"新错误"推到最前——这通常最接近根因。
- **FR-LOG-4 错误下钻**：点击某错误类型可查看原始日志样本、完整异常堆栈、
  按实例/时间的分布；支持关联同 traceId 的上下游调用链与日志。
- **FR-LOG-5 快速检索**：提供关键字、日志级别、服务/实例、时间范围的简易
  检索面板（封装 ES 查询），并支持保存常用查询。
- **FR-LOG-6 错误结论**：在故障详情页给出错误日志摘要结论，
  如"实例 X 在 14:03 起出现 N 次 `SQLException: connection timeout`，
  指向 TDSQL 连接异常"。
- **FR-LOG-7 已知错误库**：可将常见错误模式登记为"已知错误"并关联处置预案，
  再次出现时直接给出结论与建议。

### 3.5 应急处置建议（支撑"30 分钟解决"）

- **FR-4.1 处置预案库**：按故障类型/组件维护可检索的处置预案（SOP），
  支持手工维护与从历史复盘沉淀。
- **FR-4.2 智能推荐**：根据疑似根因匹配并推荐处置动作（如回滚变更、重启实例、
  限流降级、扩容、切流），并标注预期效果与风险。
- **FR-4.3 一键处置（可选/分期）**：对低风险动作（重启、扩容、回滚）支持平台内
  触发执行，需二次确认与权限校验，全程审计。
- **FR-4.4 处置效果反馈**：执行动作后持续观测健康度，确认是否恢复，未恢复则提示
  尝试下一候选方案。

### 3.6 一线运维界面（简洁、直观）

- **FR-5.1 故障大盘（首页）**：默认只展示"当前进行中故障"卡片，按 P 级排序；
  每张卡片一屏内呈现：业务名、影响概述、严重级别、持续时长、疑似根因、
  建议动作、认领按钮。无故障时显示全绿状态。
- **FR-5.2 故障详情页（三段式）**：上=业务影响摘要，中=逐层下钻的根因定位路径
  与证据（含错误日志聚合面板），下=处置建议与操作记录；
  一线人员从上往下读即可完成处置。
- **FR-5.3 一句话结论**：每个故障在顶部用一句自然语言概括
  （如"支付网关因 14:02 的配置发布导致响应时间上升，建议回滚"）。
- **FR-5.4 移动端适配**：值班场景支持手机查看故障、认领、查看建议。
- **FR-5.5 协同**：故障详情页内置处置时间线/讨论区，支持 @人、记录关键操作。

### 3.7 复盘与持续改进

- **FR-6.1 自动复盘报告**：故障恢复后自动生成报告草稿（时间线、影响、根因、
  处置、MTTD/MTTL/MTTR）。
- **FR-6.2 指标看板**：统计 1-15-30 达标率、误报率、告警收敛率、预案命中率，
  按周/月趋势呈现。
- **FR-6.3 知识沉淀**：复盘结论可一键回写到预案库与相似故障库。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 关键指标采集到告警端到端 ≤ 60 秒；故障详情页加载 ≤ 3 秒；错误日志聚合查询 ≤ 5 秒 |
| 可用性 | 监控系统自身可用性 ≥ 99.9%，且与被监控系统故障域隔离 |
| 可扩展 | 支持 400+ 应用、万级实例与监控对象；数据源（自研/采购监控工具）插件化接入 |
| ES 适配 | 查询经聚合层封装，避免大范围扫描拖垮 ES；按时间窗与对象标签精准检索 |
| 数据保留 | 原始指标 ≥ 30 天，故障事件与复盘 ≥ 1 年 |
| 安全 | 基于角色的权限控制（RBAC）；处置操作全程审计；敏感数据脱敏 |
| 易用性 | 一线人员无需培训即可看懂故障大盘；核心操作 ≤ 3 次点击 |
| 准确性 | P1/P2 故障漏报率 ≈ 0；告警误报率 ≤ 5% |

## 5. 关键数据模型（概念）

- **业务服务（BusinessService）**：业务名、负责人、SLO、依赖的微服务列表。
- **微服务（Microservice）**：TSF 服务名、所属业务、部署组、上下游依赖。
- **服务实例（Instance）**：所属微服务、部署组、IP/容器、承载主机。
- **基础设施对象（Infra）**：类型（OS/TDSQL/GaussDB/TBDS/CRedis/网络/硬件/
  外设/动环）、标识、承载的实例、来源监控工具。
- **监控指标（Metric）**：归属对象、来源工具、ES 索引、检测规则、基线。
- **日志/错误（LogEntry / ErrorPattern）**：归属对象、级别、日志模板、
  ES 索引、堆栈、traceId；ErrorPattern 记录错误模板与是否已知错误。
- **故障事件（Incident）**：级别、状态、影响业务、时间线、根因（含层级）、
  处置记录、MTTD/MTTL/MTTR。
- **变更（Change）**：类型（TSF 发布/配置/扩缩容/工单/动环事件）、对象、
  时间、操作人，用于根因关联。
- **处置预案（Runbook）**：适用故障类型、步骤、风险等级、预期效果。
- **对象映射（ObjectMapping）**：自研工具与采购工具间同一对象的归一化映射。

## 6. 验收标准

1. 注入一个典型故障（如某次错误发布），系统在 1 分钟内产生 P1 告警并推送。
2. 故障大盘首页一屏内可看清"哪个业务受影响、严重程度、疑似根因"。
3. 可从受影响业务逐层下钻至 TSF 微服务、实例、基础设施对象，路径每跳有异常证据。
4. 一键拉取异常对象的 ES 错误日志，聚合呈现错误类型并标出故障窗内的新增错误。
5. 根因候选 Top-3 中包含真实根因，且关联出对应变更。
6. 系统给出与根因匹配的处置建议，执行后健康度恢复并自动确认。
7. 故障恢复后自动生成含 MTTD/MTTL/MTTR 的复盘报告草稿。
8. 连续运行下告警误报率 ≤ 5%，告警收敛率 ≥ 80%。

## 7. 分期规划（建议）

| 阶段 | 范围 | 目标 |
| --- | --- | --- |
| 一期 | 两套监控工具与 ES 接入、对象归一化映射、异常检测、告警收敛、故障大盘、业务-微服务-基础设施拓扑与影响面 | 打通"1 分钟发现 + 看清影响" |
| 二期 | 逐层下钻、错误日志快速排查、数据库/中间件专项视图、变更关联、根因候选排序、三态联动 | 实现"15 分钟定位" |
| 三期 | 预案库、智能推荐、一键处置、已知错误库、自动复盘与指标看板 | 实现"30 分钟解决"与持续改进 |

## 8. 范围之外（本期不做）

- 不替代专业 APM/日志平台的全量存储与检索，仅做接入与关联。
- 不做业务系统的自动容量规划。
- 一键处置仅限低风险动作，复杂变更仍走标准变更流程。
